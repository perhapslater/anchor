    ⓘFind your library ID and API key

    Library ID

    1. Open the Audiobookshelf web app and select the library containing your ebooks.
    2. Copy the part immediately after /library/ in your browser's address bar. For example, in https://books.example.net/library/YOUR_LIBRARY_ID/bookshelf, copy only YOUR_LIBRARY_ID, not the library name or the full URL.
    3. Paste it into Anchor's Library ID field.

    API key (Audiobookshelf 2.26 or newer)

    1. Sign into Audiobookshelf as an administrator. Open Settings → Users → API Keys and create a key named Anchor.
    2. Select a user with access to this library and permission to download books. Make sure the key is active.
    3. Copy the key when it is displayed and paste it into Anchor's Audiobookshelf API key field. Audiobookshelf displays it only once.

    Older Audiobookshelf versions: open Settings → Users, select the account, and copy its API token.

    Users & groups

    Create accounts, assign groups, and explicitly link Tailscale and local sign-in methods.

    Keep a recovery route

    Keep at least one enabled administrator with a local password. Local sessions expire after 12 hours. Changes to passwords, sign-in details, groups or account status end password sessions. Name edits and unchanged saves keep sessions active. Updating your local credentials does not interrupt a Tailscale sign-in.

    If an administrator loses their password, stop Anchor and run this against the same configuration directory:

    anchor recover-admin YOUR_LOCAL_LOGIN

    Sign in with the temporary password, then edit your own account in Users & groups and save a new password. Protect the configuration directory and database backups: they contain credentials.

    Choose your destinations

    Notifications

    Send outage alerts and problem reports through ntfy, a webhook, or both. Each destination delivers independently. Save settings before testing.

    ntfy connection

    Create a topic on your ntfy server and subscribe to that same topic in the ntfy app. Anchor publishes messages to it.

    The access token must be able to publish to this topic. Leave it blank only if your server permits publishing without a token. Blank fields keep saved tokens; select Remove saved credential to clear one.

    Webhook connection

    For Discord, copy the webhook URL from your channel's Integrations settings. Generic JSON sends Anchor's documented event payload to an HTTPS receiver. The URL is a credential: Anchor masks it after saving and excludes it from dashboard YAML exports. Messages can include application addresses and the person reporting a problem; choose a private destination.

    Private access & automatic sign-in

    Use Tailscale to give people private access to Anchor and sign them in automatically. Once you link each person's Tailscale account, they'll see the groups and applications assigned to their Anchor account.

    How does it work?

    People need access to your Tailscale network, and each person's Tailscale email must be linked to an enabled Anchor account. When they open Anchor through its Tailscale Serve address, Anchor recognizes them and applies their existing groups and permissions.

    Applications may still require their own reachable address and sign-in. Linking an email does not install Tailscale, invite people to your network, or change network access rules.

    Your current setup

    You can continue with your current sign-in. Return to Administration → Connection info → Tailscale whenever you're ready. Skipping keeps any settings you've already saved.

    Step 1

    Connect Anchor to Tailscale

    Install Tailscale on your server and the devices that will use Anchor, and give those people access to your private network. Tailscale calls this network a tailnet. Then use Serve to give Anchor a private HTTPS address.

    Already connected? Continue to linking people below. You can save email links and finish setup before changing your deployment; your saved progress is kept.

    Show connection instructions

    Choose the setup that matches your installation. Run these commands yourself in the indicated terminal; Anchor does not execute them or change your running deployment.

    Serve commands

      Platform-specific setup notes

      Linux with Docker: use host networking for Anchor (--network host, or network_mode: host in Compose) so Anchor and the server's Tailscale share localhost.

      Unraid example: install the Tailscale plugin and set Anchor's Network Type to Host. If using Unraid's per-container Tailscale integration instead, choose Container.

      Windows / macOS with Docker: container localhost can differ from the server's localhost. Verify that your Docker configuration shares the required loopback connection, or choose Container and share its network environment with Anchor.

      Docker Compose: set Anchor's network_mode: service:tailscale, replacing tailscale with your Tailscale service name. Preserve Tailscale's state volume and Anchor's /config volume separately.

      Unraid example: its per-container Use Tailscale / Serve integration runs Tailscale in the container's network environment. Enter the container name that actually runs Tailscale.
